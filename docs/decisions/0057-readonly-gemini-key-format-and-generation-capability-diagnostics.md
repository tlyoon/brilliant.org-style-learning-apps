# Decision 0057 — No paid probe: verify declared model action, detect suspected deprecated key format

**Date:** 18 November 2026. **Resolved diagnostic-engineering incident:** BSA-20261118-198.
**Still active actual provider failure:** BSA-20261118-196 (two genuine Section9.6 new-original index6 Google ClientErrors, numeric status missing).
**Reused:** BSA-104/108 submitted-request no replay; BSA-164 local SDK compatibility; BSA-166 provider circuit; BSA-191 post-return text capture; BSA-193 new-activity probation; BSA-195 safe future HTTP classification.

The real Yoga6 worker previously returned `DIAGNOSTIC_READY_SOURCE_FREE_ONLY` after one SDK `models.get` HTTP200. A read-only GET confirms that a key can access model metadata; it does NOT establish permission/quota for `generateContent`. The actually attempted new Section9.6 activity index6 subsequently returned two `ClientError` responses, and the old code did not store HTTP codes; guessing 400/403/429 is forbidden.

**Source-free live Yoga6 evidence:** both independently configured credential slots reached `models.get` HTTP200, and the actual installed `google-genai` Model response for configured `gemini-3.8-flash` declared `generateContent` support with nonempty input and output token metadata. No generation, token counting, interactions API or paid requests were made during diagnosis.

A further read-only **format-only inspection** detected that **both configured keys start with `AIza`**, the legacy Standard API-key format. Google's official 2026 Gemini API key policy states Standard keys were due for migration to authorization keys before September 2026: https://ai.google.dev/gemini-api/docs/api-key . Prefix does NOT prove Key Type, billing status, restrictions or the cause of the two unstamped ClientErrors. Confirm the actual **Key Type** in the authenticated Google AI Studio API Keys page and view project tier, quota, billing and project access before trying any new generation; standard-to-auth key migration requires authorized owner/project administration. Creating a new key, changing project billing, attaching a service account or submitting new paid requests are NOT part of this diagnostic.

The normal `--diagnose-only` Yoga6 worker now runs `diagnose_declared_generation_support` alongside its existing source-free metadata check. The new function reads **at most two already-configured credential slots**, each with a 15-second timeout, one Google SDK `models.get` and no SDK retry. It inspects only `supported_actions` and a fixed safe key-format hint (`LEGACY_STANDARD_FORMAT_HINT`, `AUTH_FORMAT_HINT`, `UNVERIFIED_KEY_FORMAT`). It never prints the key, provider error text, project name/ID or billing account. It classifies model-action mismatch and metadata denial/rate limit as STOP, and the current all-legacy format as `MODEL_ACTION_DECLARED_LEGACY_KEY_FORMAT_REVIEW_REQUIRED`. Every return explicitly has `generationPermissionVerified=false`, `projectQuotaVerified=false`, `paidModelCalls=0`. Source-free metadata health cannot be promoted to paid scientific QA readiness. This is *not* an automatic credential rewrite or blanket proof that Standard-format keys actually caused the failure.

During integration the real Yoga6 `--diagnose-only` initially failed with a `ValueError`: the older owner `persist_status` allowlist rejected the new safe diagnostic fields. The historical BSA-164/188 checkpoint discipline is reused: expand the exact allowlist and validate nested key names, two bounded credential slots, canonical safe categories, explicitly false generation/quota claims and no extra fields; any simulated secret/provider message is refused. The normal source-free command then returned its structured diagnostic successfully, with **zero paid model calls**. Tests exercise real Google SDK Model/ClientError types, exact two-key healthy and denied/quota branches, 50/698 receipt refusal, legacy format hint, zero generation and checkpoint tamper/secret prevention.

**Provider blocker status:** BSA-196 remains ACTIVE. Model metadata GET200 and key format hint are useful evidence, **not** a reason to replay any lost request or to assert that paid Gemini review is available. Use the actual Google AI Studio **Key Type**, **Rate Limits**, **Projects**, and **Billing** screens before any separately legitimate new generation campaign. Google explicitly applies rate limits at project level, not separately for each API key: https://ai.google.dev/gemini-api/docs/rate-limits .
